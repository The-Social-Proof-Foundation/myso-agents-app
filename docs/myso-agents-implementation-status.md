| Journey | Required path and evidence | Failure cases that must stop the flow |
|---|---|---|
| Task marketplace to settlement | Buyer creates and funds a versioned task offer → seller agent accepts that exact current version → durable automation starts a run and reports progress → coordinator uses only authorized MCP actions and explicitly consented room context → artifact is stored in R2 and verified by content hash/signature → buyer accepts or disputes the verified delivery → core settlement finalizes → task and settlement receipts independently match the same task, participants, artifact hash and chain events → Activity shows the reconciled result. | Stale offer/version, wrong principal or organization, expired capability, over-cap spend, repeated event, uncertain worker effect, missing/altered artifact, unresolved dispute, or a receipt whose event/amount/actor differs must remain pending or fail closed without double execution/payment. |
| Room-based task coordination | Authorized owner/admin links or creates the task room → explicitly invites the intended agent with the past-history access disclosure → signed messages and attachments retain room identity, sender, sequence and digest → automation consumes a durable event once → worker progress is idempotently posted → removal rotates keys and verified history access follows the chosen membership policy → an agent with live `PermissionsAdmin` archives only after explicit owner confirmation and a short-lived owner-wallet signature → the finalized archive receipt confirms permanent pause with no unpause capability → task state still changes only through task actions and receipts. | Membership inferred from org/task alone, wrong-room or replayed message, signature/digest mismatch, cursor gap, duplicate side effect, permission loss during decrypt, missing/stale owner confirmation, wrong-room signature, or plaintext returned after access revocation must not be presented as verified context; unauthorized archive attempts must fail. |
| Private graph publication to P2P purchase | Authorized seller creates typed graph and coverage/evidence manifest → canonical version hash and seller publication signature are verified → listing pins that immutable version and explicit one-time/subscription terms → buyer selects agent or one organization as the audience and sees the terms → exact offer quote is rechecked → eligible agent-funded MySo purchase is bounded by live cap or escalated to owner approval → finalized receipt pins graph/version/hash/audience → entitlement grants key release → buyer retrieves/decrypts only that version in Knowledge or a consented hosted work turn → revoke/expiry blocks future key release and broadcasts a scoped invalidation to all open same-origin Knowledge views, clearing and aborting matching disclosures. The app persists no graph plaintext cache. Provider-side retention and already exported or derived content remain outside revocation control and need explicit policy/runtime verification. | Unsigned/changed manifest, seller-rights or live-authority failure, offer/quote drift, ambiguous audience, stale cap, duplicate purchase, wrong buyer/account, expired entitlement, changed ciphertext, version substitution, missing interactive/automation source consent, or private-context output without separate sharing consent must block access or inference; already exported plaintext is not claimed recallable. |
| Hosted unattended run and recovery | Owner encrypts the run and grants required room-history consent → durable automation claims it with a fenced lease → sidecar opens only the selected action_worker and issues a short-lived run-bound credential → each model/action/read boundary rechecks allowlist, live capability and MYSO cap → progress and artifacts persist → restart/replay resumes the same dispatch identity from the journal → final task/graph effects reconcile through scoped receipts → credential revokes at completion/cancel/expiry. | Owner OAuth bearer or worker seed in automation/MCP, stale lease, changed input under reused idempotency key, denied capability, expired/revoked credential, exhausted retry with uncertain side effect, or replay after terminal completion must not widen scope or duplicate an effect. |
